# Reference-data quality checks

The intended grain is one supported no-limit Hold’em history per venue-scoped hand identifier after identity quality filtering, plus separate per-player revealed-hole-card samples. Each revealed hand contributes once to a canonical starting class; a complete board additionally contributes one final-category result. A hand with multiple known players therefore contributes multiple samples, not multiple corpus hands. UCI’s grain is one labeled five-card row.

Checks cover archive SHA-256 checksums, raw-file inventory, supported variant filtering, duplicate venue/hand IDs, matching duplicate action arrays, known-card uniqueness, valid card codes, final-category counts, all 169 starting classes, class sample denominators and UCI label agreement. The importer processes every `.phh` / `.phhs` file, including multi-line action arrays with comments. No original player or hand identifiers enter the app’s JSON summary.

The first import found 21,606,087 HandHQ records, 400 above the published 21,605,687 count. A venue-scoped ID audit found 400 repeated occurrences across 147 numeric IDs in iPoker. Most repeated IDs have conflicting action histories: for example, the same ID appears in distinct records with different times. An ID-only deduplication would therefore select an arbitrary history. This is a medium-severity source identity issue with high-confidence evidence; the cause of the upstream ID reuse is not established. The importer now profiles complete string/numeric identifiers, retains one representative only when the action arrays agree, and quarantines every record in a conflicting group. It reports raw counts, repeated-ID counts, conflicting groups and excluded records separately. All records are read, and unsupported/conflicting observations are counted rather than silently folded into class frequencies. Synthetic fixtures verify both exact-repeat removal and whole-group quarantine. The final import reads 31,870 PHH files and 21,616,099 NT records. It quarantines 547 records across 147 conflicting groups, leaving 21,615,552 supported histories: 21,605,540 HandHQ, 10,000 Pluribus and 12 other NT examples. Another 76 non-NT records are counted separately. No accepted revealed sample contains a duplicate known card.

All 1,025,010 UCI rows have valid five-card layouts and labels that agree with the evaluator (zero mismatches). Separate randomized tests compare 30,000 five-, six- and seven-card pairs against an independent readable Swift evaluator, checking categories, order and ties. Existing split-pot, exact river, duplicate-card and simulation tests remain in place. These checks validate poker arithmetic; they do not validate image recognition or strategic EV.

The main analytical risk is high-severity selection bias if historical samples are interpreted as live probabilities. Unknown hole cards cannot be recovered. Revealed-card and river-completed samples are selected toward showdown, and most source hands date to July 2009. Pluribus is an experimental pool, not a present-day Bovada sample. The application therefore uses history only for explicitly labeled sample information and keeps combinatorial equity separate. There is no modern-opponent trend claim, calibrated range model or transfer of historical action frequencies into live betting advice.

Reproduction and source/licensing details are in [REFERENCE_DATA.md](REFERENCE_DATA.md). The inspectable implementation is `Tools/ReferenceDataTool/main.cpp`, its synthetic fixtures and `scripts/test-reference-tool.sh`; the aggregate evidence is `Sources/PokerCore/Resources/reference-data.json`. No SQL or Python/notebook pipeline is used. `../PokerData/manifest.json` records each downloaded archive’s exact checksum and source revision.
